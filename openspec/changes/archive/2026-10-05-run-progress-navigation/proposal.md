# 运行页进度导航包

## 为什么

需求研讨会确认：当前事件轨迹是纯文本流水账（事件类型 + 时间戳），学生看不懂"我在哪、做了什么、下一步是什么"；无法跳转历史步骤；移动端侧栏挤压主内容。需要在不加线性限制的前提下，给分支化实验流程提供"游戏关卡式"的进度感知与读档能力。

## 变更内容

**Runtime / 事件层**

- 新增学生命令 `JUMP_TO {nodeId}`：仅允许跳转到本 Run 中已进入过的节点；语义与 BACK 一致——只导航、不回滚变量/分数（事件流是唯一事实，导航只追加事件）。
- 新增事件类型 `JUMPED_TO`（payload: from/to）；访问栈重建逻辑兼容：遇 JUMPED_TO 弹栈至目标节点。

**学生端 UI**

- **里程碑进度条**：运行页顶部，从 Definition 计算 start→end 最长主路径作为里程碑刻度；当前节点高亮、已进入节点点亮、未到达灰色；超出宽度横向可滚动。
- **事件轨迹重做**：每条事件显示节点标题（不再是内部 ID）、操作摘要（选择项/变量变化/得分变化）、时间；当前节点对应事件高亮；点击历史 `NODE_ENTERED` 事件触发 JUMP_TO 读档（已完成 Run 禁用跳转）。
- **移动端适配**：≤800px 时事件轨迹从侧栏改为底部抽屉（默认收起为"轨迹 (N)"横条，点按展开半屏列表）；进度条横向可滚动。

- **实验记录背包**：运行页新增「背包」面板（与轨迹同区分页签），从事件流聚合学生已产生的记录：观察记录（OBSERVATION_SUBMITTED 全文）、问答记录（题目 + 所选答案 + 是否正确）、关键变量变化；纯前端从事件流 + Definition 派生，不新增后端接口；移动端与轨迹共用底部抽屉的分页签。

**不做（本迭代明确排除）**

- 跳转不回滚变量与分数（保持事件流不可变语义；真·状态回档后续单独立项）
- 教师端编辑器不变

## 影响

- 规格：`experiment-events`（新增事件类型）、`experiment-runtime`（新增命令）、`student-runtime-ui`（修改事件轨迹需求 + 新增进度条/跳转/移动端需求）
- 代码：`packages/experiment-events`、`packages/experiment-runtime`、`apps/api/src/runs`（命令白名单）、`apps/web`（RunPage/EventTrail/新组件）
- 兼容性：存量 Run 的事件流无 JUMPED_TO，行为不变；Definition Schema 不变
