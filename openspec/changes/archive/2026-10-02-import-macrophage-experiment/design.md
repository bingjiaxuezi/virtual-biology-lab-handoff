# Design：旧交互式视频实验 → Experiment Definition v0.1

## 素材盘点

`import/实验视频/`：43 个 MP4 + 20 张图片，约 1.9GB。文件名自带编号与正误标注（"错误"/"正确"）。`实验视频 (2).zip`（1.19GB）按重复压缩包处理，不导入。`图5 - 副本.jpg`、`bcb43f5f…png`（与图11 同尺寸同大小）按重复文件处理。

## 选择点的统一映射模式

QUESTION 节点不绑定变量、无法驱动分支，因此所有"选择 → 正误视频分支"统一用现有能力实现：

1. 每个选择点一个 ENUM 变量（如 `grip_site`，选项为操作描述）；
2. `VARIABLE_INPUT(inputMode: SELECT)` 让学生做选择；
3. Transition 按 `变量 EQ 选项` 分支到对应 MEDIA(VIDEO) 播放结果；
4. 错误分支播放错误视频后汇合回主线（实验继续，符合"试错教学"）；判定题 F 答错播放 26 后回到选择点重做；
5. 计分用 rules：`when 变量 EQ 正确选项 → SCORE +10`，与分支路径解耦，Event Log 自然记录每次选择。

## 待用户确认的假设（实现前逐条过）

- A：`3抓老鼠 选背` 无正误标注，假设为错误选项（标准抓法是颈后/头后侧皮肤，见图1）。
- D：`19大滴染色只用盖玻片`、`20先推片再盖玻片` 无标注，均假设为错误（21 标注正确）。
- F：选项内容需编写（图中辨认"被吞噬的鸡红细胞"），答错播 26 后重做，不计分只设门槛。
- G：`27请选择需要进行实验的场景` 假设为"荧光微球定量法"单入口，直接引入第二幕。
- H/I/J：选项文案按操作常识编写（保留沉淀/上清等），正确项需用户确认。
- 第二幕 31 与 33 均为"吸取腹腔液"，取 33（含"加入生理盐水"更完整）为主线，31 不上传。

## 工程方案

1. **上限配置**：`resolveAssetsConfig` 读 `ASSET_MAX_UPLOAD_MB`（默认 200），FileInterceptor 限制与 413 文案随之调整；更新 `.env.example` 与 asset-media 规格。
2. **批量导入脚本** `apps/api/scripts/import-assets.ts`：`--dir <目录>` 扫描媒体文件（跳过 zip/重复副本）→ 登录教师账号取 JWT → 逐个 POST `/api/assets/upload`（类型按扩展名映射 VIDEO/IMAGE）→ 输出 `import/asset-map.json`（文件名 → assetId/type/name）。assetId 由服务端生成，定义编写时以映射为准。
3. **定义产物** `examples/macrophage-phagocytosis.v0.1.json`：素材 assetId 以占位符书写，导入后由脚本替换为真实 assetId；过 `validateExperiment` 全量校验。
4. **入库**：脚本 `apps/api/scripts/create-macrophage-experiment.ts` 调 API 创建实验（draft = 定义）并发布 v1。
5. **验收**：Studio 画布目视检查分支结构 → 学生端走两条路径（全对 / 含错误选择）→ 教师 Runs 页核对事件轨迹与得分。

## 不做的事

- 不压缩/转码视频（保持原画质，磁盘占用接受）；
- 不引入新的节点类型或变量类型。

## 规则求值语义修复（实现中发现的缺陷）

原 `evaluateRules` 在每次 SET_VARIABLE 时对全部 Rule 重放，导致已命中的计分规则被无关变量变化反复触发。修复：`evaluateRules(definition, state, changedVariableId)` 只求值 `when.variableId === changedVariableId` 的 Rule；酶温度样板实验行为不变（规则变量即被设置的变量）。
