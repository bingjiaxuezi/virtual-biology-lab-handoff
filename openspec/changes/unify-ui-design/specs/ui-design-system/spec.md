# Spec Delta

## Purpose

定义项目级 UI 设计系统：统一的设计令牌、组件规范与优化流程机制，作为教师端与学生端所有页面的视觉基线，并为后续任何 UI 优化任务提供可复用的强制流程。

## ADDED Requirements

### Requirement: 统一设计令牌
教师端与学生端 MUST 共用同一套设计令牌定义（色彩、间距、圆角、字号、阴影），两端的 CSS 变量名 MUST 一致；新增颜色或尺寸 MUST 先进入令牌，禁止在组件中写死色值。

#### Scenario: 两端主色一致
- **WHEN** 对比教师端与学生端的主操作按钮与强调色
- **THEN** 两者解析自同名令牌且色值完全相同

#### Scenario: 新色值先入令牌
- **WHEN** 任何页面需要引入新的颜色
- **THEN** 该颜色以 CSS 变量形式定义在令牌区，组件只引用变量

### Requirement: 组件视觉规范
按钮（主/次/危险）、表单控件、面板卡片、表格、空态、加载态、错误态 MUST 有统一规范样式，同一组件在不同页面 MUST 渲染一致；交互控件 MUST 有可感知的 hover 与 disabled 状态。

#### Scenario: 主按钮跨页面一致
- **WHEN** 对比登录页与实验列表页的主按钮
- **THEN** 两者的背景色、圆角、内边距、字号完全一致

#### Scenario: 禁用态可感知
- **WHEN** 任一操作按钮处于禁用状态
- **THEN** 视觉上有明显区分（透明度或灰化），且不可点击

### Requirement: UI 优化流程机制
仓库 MUST 提供 UI 规范文档与可复用的优化流程技能；任何 UI 变更任务 MUST 先读规范、走 OpenSpec 提案，完成后 MUST 用桌面与移动两种视口的截图验收通过方可归档。

#### Scenario: 规范文档存在且被引用
- **WHEN** 新协作者或 AI 接手 UI 任务
- **THEN** 能在 `docs/design/ui-guidelines.md` 找到令牌、组件规范与验收清单

#### Scenario: 双视口截图验收
- **WHEN** 一次 UI 变更完成实现
- **THEN** 桌面与移动视口的截图均无文字溢出、元素重叠或错位

### Requirement: 登录页品牌化
教师端登录页 MUST 呈现产品名称与平台定位，表单居中、双模式（登录/注册）切换清晰，错误提示 MUST 在表单内联展示且不使布局跳动。

#### Scenario: 登录页展示品牌
- **WHEN** 教师打开登录页
- **THEN** 首屏可见产品名称「生物仿真实验平台」与登录/注册切换

#### Scenario: 错误内联展示
- **WHEN** 教师提交错误密码
- **THEN** 表单内出现错误提示且表单位置不移动
